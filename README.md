# LyricsX Next

**LyricsX Next** 是基于 [LyricsX](https://github.com/MxIris-LyricsX-Project/LyricsX) 发展、由本仓库独立维护的版本，保留原项目历史、作者署名和 MPL-2.0 协议。此前 2.0.0–2.0.24 的发布保留原名称；从 2.0.25 起使用 LyricsX Next。

> 面向 macOS 26/27 的原生 Swift 歌词播放器。保留 LyricsX 的菜单栏、搜索、导入导出和播放器控制，同时重做播放同步、缓存、悬浮窗和设置界面。

## 功能

- 支持 Apple Music、Spotify，以及 MediaRemote 能识别的其他播放器。
- Apple Music 读取当前歌曲、封面、播放进度和内嵌歌词；Spotify 和系统媒体通知提供封面回退。
- 同时搜索 LRCLIB、网易云音乐、QQ 音乐、酷狗和 Musixmatch，并支持来源排序；自动搜索补查歌名关键词、跨语言别名、副标题与 `feat.` 等写法，再选择最佳版本，搜索结果标记逐字与双语版本。
- “双语优先”“逐字优先”和“严格匹配”开关：核对歌名和歌手，时长只作辅助参考；关闭严格匹配后可选用歌手信息不完整但标题可信的同步歌词。歌词提前结束不会导致准确的歌名、歌手匹配被拒绝。
- 悬浮窗提供 Liquid Glass 和“磨砂阅读”两个可点击图例，高透玻璃可调底色透明度，磨砂阅读可调透明度与磨砂程度，并保留锁定、解锁、点击穿透、鼠标悬停显示、隐藏和自由拖动。
- 悬浮窗位置、大小、字号、透明度、翻译和下一句显示方式会被保存；无可显示歌词或纯音乐时使用紧凑的封面、歌名和歌手卡片。
- 主窗口与悬浮窗使用非线性滑入、轻微回弹和少量模糊；悬浮窗的下一句直接上移成为当前句，连续追加的歌词只对新增部分播放动画。
- 逐字绘制按真实词语或音节时间连续提亮、轻微放大；慢唱有柔和辉光。“设置 → 动效”提供放大、长音辉光、HDR 开关与 1.0×–4.0× HDR 亮度调节，支持“减少动态效果”。
- 暂停、跳转和切歌时会保留有效播放状态；单次播放器读取失败不会闪出“未识别到播放源”提示。
- 菜单栏播放控制、歌词偏移、搜索、重新搜索、Finder 定位、错误歌词停用、资料库和 Apple Music 写入。
- “设置 → 通用”可分别隐藏 Dock 图标、菜单栏图标和菜单栏歌词；重新打开应用时继续遵循 Dock 设置，隐藏后仍能使用 ⌥⌘O 打开主窗口。
- 联网搜索结果默认保存为 `.lrcx`，保留逐字时间和来源附加信息；仍可导入、读取 `.lrc` 和纯文本歌词。

## 歌词搜索

搜索页会逐步展示匹配结果，并分别显示每个来源的数量、搜索进度和异常。严格匹配开启时，准确标题有更高优先级；关闭后，通过歌曲身份校验的标题变体按时间轴、功能偏好、来源顺序排序，标题更接近不再压过来源顺序。同名但歌手明确不符的歌词不会因此变成可信匹配。

“逐字优先”和“双语优先”都开启时，依次选择逐字兼双语、仅逐字、仅双语、普通同步歌词；只开启双语优先时，双语排在逐字之前；只开启逐字优先时，没有逐字仍优先选择双语。两项都关闭时，可信同步版本按来源顺序排序。功能相同时，来源顺序高于细微匹配分差。已保存的歌词继续优先复用；要替换当前缓存，请在“设置 → 搜索”点击“重新搜索”。

自动搜索每个来源、每个查询最多下载 40 个候选。手动搜索默认使用精简模式：覆盖所有启用来源，查询完整歌曲信息、原始标题和一个清理后的标题，每个来源下载并显示最多 12 个严格可信匹配，合并同一来源中歌词正文完全相同的副本，最长等待 18 秒。即使设置中关闭“严格匹配”，同名但歌手不符、仅靠宽松规则命中的版本也不会混入精简列表。搜索页的“完整搜索”默认关闭；打开后才展开全部已验证别名、每个查询下载最多 80 个候选并等待最多 40 秒，同时保留不同版本 ID。自由输入其他关键词时不会按当前播放歌曲过滤。

自动搜索在约 1 秒的初次收集后先显示可靠歌词，并继续查找更好的版本。可靠结果取得后即写入临时缓存，切歌返回或重启可立即复用，同时继续补搜；完成搜索后再确认最终版本。最高优先级来源找到具备全部偏好功能的可靠版本时立即结束；否则，各来源完成有效查询轮次后选择已有最佳版本。找到逐字或双语版本后，补搜最多再等待约 8 秒，避免候选下载一直拖住完成；新确认的跨语言别名会获得新的补搜机会，总搜索预算仍为 24 秒。中文仅逐字、外语仅双语都可以正常完成，不必同时具备两项功能。加载期间显示“正在加载歌词”或“正在加载更多版本”；超时保留已有结果。手动重试合并旧结果后仍遵守精简数量上限。

悬浮窗辅助文字支持“仅翻译”“仅下一句”“翻译或下一句”“翻译和下一句”和“关闭”。“翻译或下一句”优先显示本句翻译，没有可用翻译时才显示下一句；自动高度只为实际显示的辅助文字留出空间，内容改变后立即开始收缩或展开。

逐字标签依据实际可用的时间标记；允许零时长字符、未标记的标点和重叠时间，不会因为其中一个异常字符移除整句动画。普通 LRC 不会凭空生成逐字时间。网易云逐字歌词也会合并对应翻译。

## 歌词动效

悬浮窗保持一个当前歌词绘制层，至多保留一条正在退出的旧句。旧句立即向上移动、模糊并淡出，通常 0.16 秒内移除，高速歌词进一步缩短；暂停也不会冻结退出过程。下一句沿用相同的换行排版，从预览位置平滑上移、放大，移动过程中带轻微模糊。底部的新下一句和变化的翻译单独平滑淡入，普通换句不再模糊标题和歌手。主歌词为两行时，为翻译和下一句分别保留空间。活动行和未活动行持续复用同一文字视图；主窗口关闭或开始最小化时暂停其连续绘制与自动滚动，悬浮窗继续使用独立的播放时钟。

相邻、间隔不超过 1.2 秒且严格追加在原文末尾的歌词，会保持已有文字的位置，只让新增内容出现。普通整句替换保留滑入和模糊。逐字时间由歌词源决定，可能是词、音节或字符，不会把缺失时间的普通 LRC 伪造成逐字歌词。

长音辉光按单个时间片段的长度渐进增强：超过约 0.45 秒开始具备辉光，约 1 秒的慢唱已有可见效果，约 1.6 秒达到完整强度；不会把辉光固定在最后一个字母。在“设置 → 动效”点击“关闭 / 开启”图例卡片切换辉光，两张图使用相同歌词和普通亮度，直接比较光晕效果。HDR 辉光增强默认开启，亮度默认 1.6×，可在设置调到 1.0×–4.0×；手动关闭后会记住选择，升级也保留已保存的开关值。普通亮度下的辉光同样增强，无需打开 HDR 才能看见长音效果。

设置按显示器列出“EDR 支持”，依据 macOS 报告的潜在扩展亮度余量判断，不按电脑型号屏蔽，也不将该结果视为 XDR 等级或固定峰值亮度认证。每个窗口按自己所在屏幕选择输出范围，辉光目标强度限制在该屏幕的潜在余量内；实际亮度仍由屏幕和系统决定。没有 EDR 余量时自动使用普通辉光，开关偏好继续保留。具体亮度余量可在“开发者选项 → 显示诊断”查看。

可见的活动歌词使用绑定各自原生窗口的显示刷新回调，根据当前屏幕最高刷新率直接采样播放时钟，并在窗口交互循环中继续更新。“设置 → 动效 → 悬浮窗帧率”可单独将悬浮窗限制为 60 帧；默认继续跟随屏幕，选择会保存，主窗口不受影响。60 帧保留全部效果，但高刷新率屏幕上的运动细腻度会降低。实测方法与局限见 [性能记录](docs/performance/resource-audit-2.0.34.md)。暂停、隐藏或没有活动时间片段时停止连续绘制。文字排版按内容、字号、环境和可用尺寸缓存，位置、缩放和辉光变化不重新测量整窗。逐字的连续刷新只作用于主歌词，翻译与下一句复用静态排版。快速行级歌词会缩短切换动画并加密行边界检查；主窗口隐藏时冻结列表选中行和进度控件，再次显示时恢复当前进度。

### 悬浮窗自动高度

宽度始终沿用用户设置，只根据当前原文、实际辅助行及换行计算高度。文字测量与渲染共用显式字号和换行结果，避免预留两行却自动缩成一行产生大块上方空白。极长内容最多两行，必要时适度减小字号。

新高度立即进入非线性缩放动画，不再等待短句稳定或忽略较小的高度差。顶部和水平中心保持固定；玻璃窗口缩放时保留同一个歌词宿主与固定绘制宽度。连续增量歌词仍为同一段预留布局，避免逐个字符改变窗口大小。歌词加载中、前奏和间奏保留顶部歌名与歌手，正文显示三个小点，高度收至 96 pt。确认无歌词或纯音乐时保留歌曲信息卡片，封面、歌名与歌手整体居中。

### 悬浮窗样式

“设置 → 悬浮窗 → 外观”提供 Liquid Glass 和“磨砂阅读”两种样式，使用等宽、对齐的可点击图例。两者都使用 Apple 官方的 `NSGlassEffectView`：Liquid Glass 使用 `.clear`，边缘保留原生光学效果，再平滑过渡到中央阅读区；磨砂阅读使用 `.regular` 更充分地柔化背景，并采用较浅的阅读底色。两种样式均保留深色到通透的渐变，不另画整圈高光描边，也不叠加第二块玻璃。

首次启动默认使用高透 Liquid Glass，底色透明度 60%，开启悬浮窗显示和“鼠标经过时隐藏”。鼠标经过隐藏在锁定后生效，解锁后可拖动窗口。升级保留字体、颜色、歌词来源、偏移与悬浮窗位置；旧透明度换算为独立的玻璃底色设置，磨砂阅读继续使用已保存的参数。

Liquid Glass 的透明度范围为 0–100%，只改变内部从顶部向下逐渐透明的底色；原生光学层保持完整，不会因滑块变淡而丢失亮边与折射。纯色背景下变化可能不明显。磨砂阅读的透明度仍为 20–80%，磨砂强度为 0–100%。旧 Liquid Glass 磨砂值保留用于兼容，新高透材质由系统管理模糊；需要更强柔化时可选择磨砂阅读。系统开启“降低透明度”时使用实色背景。

“设置 → 通用”可设置应用深色、浅色或跟随系统；磨砂悬浮窗可在其外观设置中单独调整，Liquid Glass 保持统一高透外观。歌词和逐字配色会按背景模式保护对比度。

原生折射由 macOS 绘制，不采集屏幕重绘。材质切换只替换光学视图，保留歌词宿主；透明度变化与窗口高度动画复用材质。逐字绘制按当前屏幕刷新时刻采样，减少帧间抖动；隐藏时停止不需要的绘制。EDR 输出按窗口生命周期恢复，实际亮度由显示器和系统决定。

2.0.35 的更新介绍使用正式应用的材质、歌词与主窗口组件实时渲染，也可打开独立演示悬浮窗。演示不连接播放器、不保存歌词、不改动个人配置；退出介绍后释放演示窗口与刷新任务。首次安装显示完整教程，升级后首次打开显示更新介绍，之后可从“设置 → 关于”重看。

2.0.36 的 Liquid Glass 歌词配色按当前设置自动处理：默认配色优化可读性，自定义颜色、逐字独立配色或跟随封面时不额外改色；恢复默认配色后自动恢复优化，无需手动开关。升级后首次打开会显示本次更新介绍。

主窗口的歌词滚动位置按歌曲和歌词版本独立管理。切歌或重新载入歌词后，前奏尚未进入第一句时停在列表顶部；进入歌词后平滑跟随当前句，清除上一首的手动浏览状态与延迟返回任务。

## 设置

设置按通用、播放器、悬浮窗、歌词、动效、搜索分类。每项提供用途说明，并说明会影响交互、能耗、联网或文件数据的情况。缓存文件夹、导入导出、Apple Music 写入、Musixmatch 令牌与批量恢复搜索集中到独立的“开发者选项”；原有菜单栏入口继续保留。令牌输入框仅在打开开发者选项时加载，令牌保存在系统钥匙串中供歌词源使用。

## 安装

从 [Releases](https://github.com/wzk112/LyricsX-Next/releases) 下载最新的 `LyricsX-Next-2.0.36.zip`，解压后将 `LyricsX Next.app` 拖到 `/Applications`。从旧版升级时先退出旧应用，并移除旧的 `LyricsX.app`，避免同时启动两份。应用标识与缓存目录保持兼容，已有设置及歌词无需迁移。

本次包使用本机 ad-hoc 签名，没有 Developer ID 公证票据。首次打开时如果 macOS 提示无法验证开发者：

1. 在 Finder 中双击一次 LyricsX Next。
2. 打开“系统设置 → 隐私与安全性”，点击“仍要打开”。
3. 如果系统仍提示应用已损坏，重新下载并解压；必要时执行：

   ```sh
   xattr -dr com.apple.quarantine "/Applications/LyricsX Next.app"
   ```

完整的安装、签名和版本说明见 [`docs/releases/v2.0.36.md`](docs/releases/v2.0.36.md)。

## 播放器权限

第一次读取 Apple Music 或 Spotify 时，macOS 可能要求允许 LyricsX Next 自动化控制播放器。允许后重启 LyricsX Next 即可。也可以在“系统设置 → 隐私与安全性 → 自动化”中检查权限。

如果自动模式没有找到正在播放的歌曲，可在“设置”中选择 Apple Music 或 Spotify。Apple Music 的本地歌曲还会读取文件位置和内嵌歌词；没有内嵌歌词时会继续使用联网搜索。

## 缓存和歌词格式

默认缓存目录是 `~/Music/LyricsX`，可以在“设置”中选择已有目录。应用会优先读取磁盘中的现有 `.lrcx`、`.lrc` 文件，选择另一份搜索结果后会更新原文件，不产生重复缓存。

2.0.8 起，尚未完成搜索的可靠结果也会写入同一缓存文件，以一个临时标记记录搜索状态，歌词正文、翻译和逐字时间不变。重新进入歌曲时立即显示并继续搜索；手动选择和已确认的缓存不会被临时结果覆盖。

2.0.1 起，新缓存恢复使用 `.lrcx`。它会保留逐字时间、翻译、偏移和来源附加信息；普通 `.lrc` 继续支持导入和读取。

如需重新获取所有歌词，可关闭应用后删除 `~/Music/LyricsX` 中的缓存文件，再启动 LyricsX 搜索或播放歌曲。

## 从源码构建

需要 macOS 26 或更高版本以及 Swift 6.2+：

```sh
swift test --no-parallel
LYRICSX_WINDOW_QA=1 swift test --filter WindowFrameTests
./scripts/build.sh release
open "build/LyricsX Next.app"
```

`scripts/build.sh release` 会构建 App、复制 MediaRemote 组件、生成图标、使用 ad-hoc 签名并执行严格签名校验。默认签名身份为 `-`；正式公开分发应在本机配置 Developer ID、Hardened Runtime 和 notarization。

原生窗口测试需要有桌面会话，并在单独进程中运行自己的 AppKit 事件循环。常规测试串行运行，避免像素渲染占用主线程时干扰搜索、缓存测试的异步截止时间。

## 项目结构

```text
Sources/LyricsXCore       播放快照、歌词模型、时间轴和身份校验
Sources/LyricsXServices   播放器桥接、歌词搜索、缓存和编码
Sources/LyricsXApp        SwiftUI 主窗口、设置、菜单栏和悬浮窗
Vendor/LyricsKit          包含来源修复的 LyricsKit 固定源码和原许可证
Tests/                    时间轴、缓存、来源优先级、播放器和窗口回归测试
Legacy/LyricsX            原 LyricsX 项目
Legacy/LyricsXPackage     原 LyricsXPackage 项目
```
